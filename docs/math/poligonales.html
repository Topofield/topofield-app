1. Mapa del código

El cálculo vive en src/lib/calculations/. Son funciones puras de TypeScript: no usan React, ni Supabase, ni nada del navegador. Reciben un objeto con los datos de campo y devuelven otro con los resultados.

ArchivoQué hace
angles.tsConvierte ángulos entre grados-minutos-segundos y decimal (con acarreo de desbordamiento), normaliza azimuts al rango [0°, 360°) y expone trigonometría en grados (cosDeg, sinDeg).
tolerances.tsConstantes de tolerancia angular y precisión relativa mínima por orden de precisión (PRD § 5.4).

2. Convenciones

2.1. Ángulos en grados, minutos y segundos

El usuario captura los ángulos en su forma natural de campo (DMS). Para los cálculos se pasa a grados decimales:

decimal = grados + minutos / 60 + segundos / 3600

Y se vuelve a DMS para mostrar resultados. Al volver a DMS se acarrea el desbordamiento (60″ → +1′; 60′ → +1°) para no devolver nunca 60 en minutos o segundos. En angles.ts:

export function dmsToDecimal(deg, min, sec) {
  const sign = deg < 0 ? -1 : 1;
  return sign * (Math.abs(deg) + min / 60 + sec / 3600);
}

2.2. Convención de azimut

El azimut de cada lado se obtiene del azimut del lado anterior y del ángulo medido en la estación que los une. La fórmula difiere según el tipo de poligonal porque los datos de campo son distintos:

TipoFórmula del azimut del lado i
CerradaAzi = Azi−1 + 180° − ángulo internoi
Abierta sin controlAzi = Azi−1 + 180° + ángulo horizontali
Abierta con controlAzi = Azi−1 ± deflexióni  (+ derecha · − izquierda)

Todo se normaliza a [0°, 360°) con normalizeAzimuth.

Nota: en la poligonal cerrada las dos orientaciones del recorrido (horario y antihorario) producen polígonos espejo que igualmente cierran, porque Σ(180 ± α) es siempre múltiplo de 360°. Por eso la convención debe ser fija; no se puede autodetectar. La que se usa es la del caso 1 del marco teórico (+ 180° − ángulo).

export function angularTolerance(order, n) {
  return ANGULAR_TOLERANCE_K[order] * Math.sqrt(n);
}

3. Tres tipos de poligonal

3.1. Cerrada — computeClosed

El recorrido empieza y termina en el mismo punto formando un polígono. La suma de los ángulos internos debe valer (n − 2) · 180°; cualquier diferencia es el error angular, que se distribuye equitativo entre las n estaciones antes de propagar los azimuts.

Pasos:

  1. Verificación angular: error_angular = Σ α − (n − 2) · 180° (en segundos: × 3600).
  2. Corrección equitativa: a cada ángulo se le suma − error / n (en decimal).
  3. Azimut del lado 0 = azimut de partida; cada lado siguiente con la convención cerrada.
  4. Proyecciones: ΔN = d · cos(Az), ΔE = d · sin(Az).
  5. Error de cierre lineal: √((Σ ΔN)² + (Σ ΔE)²). Perímetro y precisión relativa P / error (se expresa como 1:X).
  6. Se aplica el método de corrección elegido (sección 4) para distribuir el error lineal.

Una poligonal cerrada cumple si pasa ambas tolerancias (angular y lineal); de lo contrario solo se puede cerrar como "rechazada".

3.2. Abierta con control — computeOpenControlled

Empieza en un punto conocido y termina en otro punto conocido distinto. Las direcciones se miden como deflexiones (giro a derecha o izquierda desde la prolongación del lado anterior).

Pasos:

  1. Si se da el azimut de llegada conocido y la deflexión en la última estación, se hace cierre angular: se propagan las deflexiones crudas hasta la dirección de llegada y se compara con el azimut conocido. El error angular se reparte equitativo entre las deflexiones.
  2. Con las deflexiones corregidas, se propaga el azimut de cada lado.
  3. Proyecciones y coordenadas calculadas igual que en la cerrada.
  4. Cierre lineal contra el punto conocido: (Ncalc − Nconocida, Ecalc − Econocida).
  5. Se aplica el método de corrección.

Si falta el azimut de llegada o la deflexión final, el cálculo omite el cierre angular y solo hace el lineal — degrada con elegancia sin perder la parte de la verificación que sí es calculable.

3.3. Abierta sin control — computeOpenUncontrolled

Empieza en un punto conocido pero no termina en otro punto conocido. No hay cierre que verificar; las coordenadas se aceptan tal cual resultan. Solo se recomienda para reconocimientos preliminares; la app la marca como "sin verificación de cierre".

El cálculo es trivial: propagar azimuts con la convención horizontal, proyectar y encadenar coordenadas. No hay corrección.

4. Tres métodos de corrección

Los métodos aplican cuando hay un error de cierre lineal que distribuir (cerrada y abierta con control). Cada uno reparte ese error de manera distinta.

4.1. Bowditch (brújula)

Reparte el error proporcionalmente a la longitud de cada lado. Es el método más usado en la práctica profesional cuando ángulos y distancias se midieron con precisión parecida.

Corr_ΔNi = − Error_N · ( di / perímetro )
Corr_ΔEi = − Error_E · ( di / perímetro ) 
if (method === "bowditch") {
  for (let i = 0; i < n; i++) {
    const ratio = perimeter > 0 ? distances[i] / perimeter : 0;
    correctedDeltaN.push(deltaN[i] - errorN * ratio);
    correctedDeltaE.push(deltaE[i] - errorE * ratio);
  }
}

4.2. Tránsito

Reparte el error según las proyecciones absolutas, dando más peso a los lados con proyección grande en cada eje. Es más apropiado cuando la precisión angular supera a la lineal (estación total con cinta, por ejemplo).

Corr_ΔNi = − Error_N · ( |ΔNi| / Σ|ΔN| )
Corr_ΔEi = − Error_E · ( |ΔEi| / Σ|ΔE| )

4.3. Crandall (mínimos cuadrados ponderados sobre distancias)

Mantiene los ángulos como inalterables y ajusta solo las distancias para que la poligonal cierre. Es un caso de mínimos cuadrados con peso = 1/d.

Planteamiento:

Minimizar:   Σ ( δdi² / di )
Sujeto a:    Σ δdi · cos(Azi) = − Error_N  y  Σ δdi · sin(Azi) = − Error_E

Por multiplicadores de Lagrange se obtiene δdi = di·(λ₁·cos(Azi) + λ₂·sin(Azi)), donde λ₁ y λ₂ resuelven el sistema lineal 2×2:

[ Σ d·cos²    Σ d·cos·sin ]  [ λ₁ ]   [ −Error_N ]
[ Σ d·cos·sin  Σ d·sin²   ] · [ λ₂ ] = [ −Error_E ]

Una vez resuelto, la proyección corregida del lado i es ΔN_corri = (di + δdi) · cos(Azi) y análogo para ΔE.

Es uno de los fixtures de los tests automáticos. Con números concretos se ve cómo cada método produce un resultado distinto a partir del mismo error de cierre.

  • Tipo: cerrada, 4 vértices A, B, C, D.

5.3. Corrección por Crandall

Sumas auxiliares:

a₁₁ = Σ d · cos² = 100.4·1 + 100·0 + 100·1 + 100·0 = 200.4
a₂₂ = Σ d · sin² = 0 + 100·1 + 0 + 100·1 = 200
a₁₂ = Σ d · cos · sin = 0  (cos·sin = 0 en azimuts axiales)
det = 200.4 · 200 − 0 = 40 080

Solución del sistema 2×2:

λ₁ = ( a₂₂ · (−Error_N) − a₁₂ · (−Error_E) ) / det = (200 · (−0.4) − 0) / 40 080 = −0.001996
λ₂ = ( −a₁₂ · (−Error_N) + a₁₁ · (−Error_E) ) / det = 0

Correcciones por distancia δdi = di · (λ₁·cos(Az) + λ₂·sin(Az)):

Las proyecciones corregidas ΔN_corri = (di + δdi) · cos(Azi) coinciden exactamente con las del Tránsito en este ejemplo (±100.1996 en los dos lados que proyectan sobre N). Coordenada B con Crandall: N = +100.1996.

Para este cuadrado axial los métodos Tránsito y Crandall dan el mismo resultado porque los productos cos · sin se anulan; en una poligonal con azimuts no axiales los dos divergen y se ven sus diferencias en la práctica.

Ciclo de verificación recomendado para una poligonal real:

  1. Capturar los datos en el editor y observar las columnas calculadas en vivo.
  2. Comparar azimuts, ΔN/ΔE y error de cierre con la plantilla Excel (docs/templates/poligonales.xlsx).
  3. Comparar coordenadas corregidas por cada método; los tres deben converger en los lados más relevantes y diferir en la magnitud que el ejemplo trabajado anticipa.
