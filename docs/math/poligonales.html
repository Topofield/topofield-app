1. Mapa del código

El cálculo vive en src/lib/calculations/. Son funciones puras de TypeScript: no usan React, ni Supabase, ni nada del navegador. Reciben un objeto con los datos de campo y devuelven otro con los resultados.

tolerances.tsConstantes de tolerancia angular y precisión relativa mínima por orden de precisión (PRD § 5.4).

2. Convenciones

2.1. Ángulos en grados, minutos y segundos

El usuario captura los ángulos en su forma natural de campo (DMS). Para los cálculos se pasa a grados decimales:

decimal = grados + minutos / 60 + segundos / 3600

Y se vuelve a DMS para mostrar resultados. Al volver a DMS se acarrea el desbordamiento (60″ → +1′; 60′ → +1°) para no devolver nunca 60 en minutos o segundos. En angles.ts:

export function dmsToDecimal(deg, min, sec) {
  const sign = deg < 0 ? -1 : 1;
  return sign * (Math.abs(deg) + min / 60 + sec / 3600);
}

2.2. Convención de azimut

El azimut de cada lado se obtiene del azimut del lado anterior y del ángulo medido en la estación que los une. La fórmula difiere según el tipo de poligonal porque los datos de campo son distintos:

TipoFórmula del azimut del lado i
CerradaAzi = Azi−1 + 180° + ánguloi
Abierta sin controlAzi = Azi−1 + 180° + ángulo horizontali
Abierta con controlAzi = Azi−1 ± deflexióni  (+ derecha · − izquierda)

Todo se normaliza a [0°, 360°) con normalizeAzimuth.

Nota: en la poligonal cerrada las dos orientaciones del recorrido (horario y antihorario) producen polígonos espejo que igualmente cierran, porque Σ(180 ± α) es siempre múltiplo de 360°. Por eso la convención debe ser fija; no se puede autodetectar. Desde la Fase 7 es la del instrumento —cero en la vista atrás y giro a la derecha—, + 180° + ángulo: con ángulos interiores el recorrido es antihorario y con exteriores, horario. El caso 1 del marco teórico usa + 180° − ángulo, la convención anterior. Con amarre, el primer lado sale del azimut hacia el amarre más el ángulo de orientación (Fase 26).

2.3. Tolerancias por orden de precisión (§ 5.4)

OrdenTolerancia angularPrecisión relativa mínima
Primer orden (geodésico)1″ · √n1:100 000
Segundo orden (control urbano)5″ · √n1:20 000
Tercer orden (topográfico)15″ · √n1:5 000
Ordinario (rural)30″ · √n1:3 000

donde n es el número de ángulos que entran en la condición angular: los vértices de una cerrada —más el de cierre si la cartera cierra contra el amarre— o las deflexiones de una abierta con control. Implementación (tolerances.ts):

export function angularTolerance(order, n) {
  return ANGULAR_TOLERANCE_K[order] * Math.sqrt(n);
}

El orden alcanzado se detecta (Fase 35). No se declara: es el más alto que cumple a la vez la tolerancia angular y la precisión relativa mínima (detectPrecisionOrder). En la cartera TT4, el error angular de 12″ con n = 7 cabe en segundo orden (5″·√7 = 13.2″), pero la precisión 1:7 045 no llega a 1:20 000; en tercer orden cumple las dos (39.7″ y 1:5 000): tercer orden. Si no alcanza ni el ordinario, no tiene orden; una abierta sin control no tiene cierre que juzgar.

3. Tres tipos de poligonal

3.1. Cerrada — computeClosed

El recorrido empieza y termina en el mismo punto formando un polígono. La suma de los ángulos internos debe valer (n − 2) · 180°; cualquier diferencia es el error angular, que se distribuye equitativo entre los ángulos de la condición antes de propagar los azimuts.

El tipo de ángulo se detecta (Fase 35). Con ángulos exteriores la suma teórica es (n + 2) · 180°, y con fila de cierre contra el amarre las dos suman además 360°·k. Interiores y exteriores difieren en 720°, mucho más que cualquier error de campo, así que la suma observada dice sin ambigüedad cuál se midió (detectAngleType): el tipo cuya suma teórica queda más cerca.

Pasos:

  1. Verificación angular: error_angular = Σ α − (n − 2) · 180° (en segundos: × 3600).
  2. Corrección equitativa: a cada ángulo se le suma − error / n (en decimal).
  3. Azimut del lado 0 = azimut de partida; cada lado siguiente con la convención cerrada.
  4. Proyecciones: ΔN = d · cos(Az), ΔE = d · sin(Az).
  5. Error de cierre lineal: √((Σ ΔN)² + (Σ ΔE)²). Perímetro y precisión relativa P / error (se expresa como 1:X).
  6. Se aplica el método de corrección elegido (sección 4) para distribuir el error lineal.

El orden alcanzado es el más alto cuyas dos tolerancias, angular y lineal, cumple (§ 2.3). Desde la Fase 35 la poligonal no se cierra: queda calculada, y su informe alerta si no alcanza ningún orden.

El ángulo de orientación. Con amarre, el primer ángulo se mide desde la referencia. Si la cartera cierra contra el amarre (TT4), entra en la condición y los métodos proporcionales lo corrigen como uno más: en la TT4, −12″/7 = −1.71″ en cada uno de los 7 ángulos. Si cierra contra el primer lado (Sede Vivero), no entra: fija el datum. Mínimos cuadrados lo fija como datum siempre (§ 4.4).

3.2. Abierta con control — computeOpenControlled

Empieza en un punto conocido y termina en otro punto conocido distinto. Las direcciones se miden como deflexiones (giro a derecha o izquierda desde la prolongación del lado anterior).

Pasos:

  1. Si se da el azimut de llegada conocido y la deflexión en la última estación, se hace cierre angular: se propagan las deflexiones crudas hasta la dirección de llegada y se compara con el azimut conocido. El error angular se reparte equitativo entre las deflexiones.
  2. Con las deflexiones corregidas, se propaga el azimut de cada lado.
  3. Proyecciones y coordenadas calculadas igual que en la cerrada.
  4. Cierre lineal contra el punto conocido: (Ncalc − Nconocida, Ecalc − Econocida).
  5. Se aplica el método de corrección.

Si falta el azimut de llegada o la deflexión final, el cálculo omite el cierre angular y solo hace el lineal — degrada con elegancia sin perder la parte de la verificación que sí es calculable.

3.3. Abierta sin control — computeOpenUncontrolled

Empieza en un punto conocido pero no termina en otro punto conocido. No hay cierre que verificar; las coordenadas se aceptan tal cual resultan. Solo se recomienda para reconocimientos preliminares; la app la marca como "sin verificación de cierre".

El cálculo es trivial: propagar azimuts con la convención horizontal, proyectar y encadenar coordenadas. No hay corrección.

4. Métodos de corrección

Los métodos aplican cuando hay un error de cierre lineal que distribuir (cerrada y abierta con control). Brújula, Tránsito y Crandall corrigen primero los ángulos —el reparto equitativo de la sección 3— y después reparten el error lineal, cada uno a su manera; mínimos cuadrados lo hace todo a la vez. El orden alcanzado no depende del método: se juzga con el error de la cartera tal como se midió.

4.1. Brújula (Bowditch)

Reparte el error proporcionalmente a la longitud de cada lado. Es el método más usado en la práctica profesional cuando ángulos y distancias se midieron con precisión parecida.

Corr_ΔNi = − Error_N · ( di / perímetro )
Corr_ΔEi = − Error_E · ( di / perímetro )

Su factor es k = −Error / P por eje: en la TT4, −0.0000727 en N y +0.000122 en E (P = 115.712 m).

if (method === "bowditch") {
  for (let i = 0; i < n; i++) {
    const ratio = perimeter > 0 ? distances[i] / perimeter : 0;
    correctedDeltaN.push(deltaN[i] - errorN * ratio);
    correctedDeltaE.push(deltaE[i] - errorE * ratio);
  }
}

4.2. Tránsito

Reparte el error según las proyecciones absolutas, dando más peso a los lados con proyección grande en cada eje. Es más apropiado cuando la precisión angular supera a la lineal (estación total con cinta, por ejemplo).

Corr_ΔNi = − Error_N · ( |ΔNi| / Σ|ΔN| )
Corr_ΔEi = − Error_E · ( |ΔEi| / Σ|ΔE| )

Su factor es la corrección unitaria de cada eje, kN = −Error_N / Σ|ΔN| y kE = −Error_E / Σ|ΔE|: en la TT4, Σ|ΔN| = 83.850 m y Σ|ΔE| = 52.085 m. Lo que la hoja de Excel llama «corrección unitaria» en su pestaña de Brújula es este factor del Tránsito.

4.3. Crandall (mínimos cuadrados ponderados sobre distancias)

Mantiene los ángulos como inalterables y ajusta solo las distancias para que la poligonal cierre. Es un caso de mínimos cuadrados con peso = 1/d.

Planteamiento:

Minimizar:   Σ ( δdi² / di )
Sujeto a:    Σ δdi · cos(Azi) = − Error_N  y  Σ δdi · sin(Azi) = − Error_E

Por multiplicadores de Lagrange se obtiene δdi = di·(λ₁·cos(Azi) + λ₂·sin(Azi)), donde λ₁ y λ₂ resuelven el sistema lineal 2×2:

[ Σ d·cos²    Σ d·cos·sin ]  [ λ₁ ]   [ −Error_N ]
[ Σ d·cos·sin  Σ d·sin²   ] · [ λ₂ ] = [ −Error_E ]

Una vez resuelto, la proyección corregida del lado i es ΔN_corri = (di + δdi) · cos(Azi) y análogo para ΔE. Sus factores son λ₁ y λ₂: en la TT4, λ₁ = −1.125 × 10⁻⁴ y λ₂ = +3.392 × 10⁻⁴.

4.4. Mínimos cuadrados (Fase 14)

Ajusta ángulos y distancias a la vez por ecuaciones de condición, cada observación según su peso: v = −Q·Aᵀ·(A·Q·Aᵀ)⁻¹·w, con Q = diag(σ²), iterando porque las condiciones no son lineales en los ángulos. La cerrada tiene tres condiciones —la suma angular, ΣΔN = 0 y ΣΔE = 0—; la abierta con control, las dos de llegada más la angular si hay azimut de llegada. La calidad del ajuste la dice σ₀ = √(vᵀPv / r), leída con la prueba χ² al 95 % de su redundancia r.

El datum. El ángulo de orientación no se ajusta: un error suyo rota la poligonal entera sin afectar al cierre, así que las condiciones no lo determinan. Por eso el azimut V10 → D1 de la TT4 sale 181°51′02.5″ con Brújula —que reparte −1.71″ también a la orientación— y 181°51′04.2″ con mínimos cuadrados. Las dos cosas son correctas.

4.5. La precisión de cada punto (Fase 39)

El ajuste dice también cuánto se puede confiar en cada coordenada. El cofactor de las observaciones ajustadas sale de las matrices de la última iteración: Ql̂ = Q − Q·Aᵀ·(A·Q·Aᵀ)⁻¹·A·Q. El punto de la estación i es la partida más los lados 0…i−1, así que su jacobiano J = ∂(N, E)/∂l es la suma parcial de las filas de cierre: un ángulo de la estación j ≥ 1 arrastra los lados k ≥ j, con ∂N/∂αj = −Σ ΔEk y ∂E/∂αj = +Σ ΔNk (k de j a i−1, por radián), y la distancia k < i entra con cos Azk y sen Azk. La covarianza del punto es ΣNE = σ₀²·J·Ql̂·Jᵀ, con el σ₀ del ajuste.

La elipse. Sus semiejes son las raíces de los autovalores de ΣNE, y el mayor apunta al azimut ½·atan2(2σNE, σN² − σE²) (Ghilani y Wolf, Adjustment Computations, 4.ª ed., § 19.2). La estándar se lleva al 95 % multiplicándola por c = √(2·F(0.05, 2, r)) (ec. 19.22). Con dos grados de libertad en el numerador, F tiene forma cerrada, F = (r/2)·(α−2/r − 1), que reproduce la tabla 19.2: con r = 3, F = 9.55 y c = 4.371; con r = 2, F = 19 y c = 6.164. Es grande porque una poligonal simple solo se comprueba con su cierre. La partida, la vuelta a ella y la llegada conocida son fijas y no tienen elipse.

Ejemplo: Vivero, con los pesos de la hoja (2″, 0.011 m, 2 mediciones), σ₀ = 0.698 y r = 3:

Puntoσ N (mm)σ E (mm)Semieje mayor 95 % (mm)Semieje menor 95 % (mm)Azimut del mayor

5. Ejemplo trabajado — cuadrado con un lado largo

Es uno de los fixtures de los tests automáticos. Con números concretos se ve cómo cada método produce un resultado distinto a partir del mismo error de cierre.

Datos:

  • Tipo: cerrada, 4 vértices A, B, C, D.

  • Punto de partida: (0, 0). Azimut de partida: 0°. Orden: tercer orden.

5.3. Corrección por Crandall

Sumas auxiliares:

a₁₁ = Σ d · cos² = 100.4·1 + 100·0 + 100·1 + 100·0 = 200.4
a₂₂ = Σ d · sin² = 0 + 100·1 + 0 + 100·1 = 200
a₁₂ = Σ d · cos · sin = 0  (cos·sin = 0 en azimuts axiales)
det = 200.4 · 200 − 0 = 40 080

Solución del sistema 2×2:

λ₁ = ( a₂₂ · (−Error_N) − a₁₂ · (−Error_E) ) / det = (200 · (−0.4) − 0) / 40 080 = −0.001996
λ₂ = ( −a₁₂ · (−Error_N) + a₁₁ · (−Error_E) ) / det = 0

Correcciones por distancia δdi = di · (λ₁·cos(Az) + λ₂·sin(Az)):

Las proyecciones corregidas ΔN_corri = (di + δdi) · cos(Azi) coinciden exactamente con las del Tránsito en este ejemplo (±100.1996 en los dos lados que proyectan sobre N). Coordenada B con Crandall: N = +100.1996.

Para este cuadrado axial los métodos Tránsito y Crandall dan el mismo resultado porque los productos cos · sin se anulan; en una poligonal con azimuts no axiales los dos divergen y se ven sus diferencias en la práctica.

El conjunto de pruebas automatizadas (Vitest) cubre los tres archivos de cálculo. Al cerrar la Fase 3, npm run test ejecutaba 26 pruebas (las cifras de hoy están en la § 9 de docs/tecnica/README.md):

Ciclo de verificación recomendado para una poligonal real:

  1. Capturar los datos en el editor y observar las columnas calculadas en vivo.
  2. Comparar azimuts, ΔN/ΔE y error de cierre con la plantilla Excel (docs/templates/poligonales.xlsx).
  3. Comparar coordenadas corregidas por cada método; los tres deben converger en los lados más relevantes y diferir en la magnitud que el ejemplo trabajado anticipa.
